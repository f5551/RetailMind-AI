## 1. السبب الجذري لمظهر الداشبورد المظلم والإصلاح المنفذ (Root-Cause Investigation)

### التحقيق ورصد الخلل
أظهر الفحص الدقيق لكود تطبيق Streamlit وجود تعارض حرج تسبب في بقاء مظهر الداكن القديم في المتصفح:
1. **حقن CSS قديم ومخالف في `app.py`:**
   في الأسطر 96–142 من `app.py`، كان يتم حقن كتلة `<style>` قديمة تعود للمراحل الأولى للمشروع تتضمن:
   ```css
   .main { background-color: #0e1117; }
   h1, h2, h3 { color: #f8fafc; font-weight: 700; }
   .metric-card { background: linear-gradient(135deg, #1e293b 0%, #0f172a 100%); }
   ```
   هذا الكود كان يفرض خلفية سوداء/داكنة على جسم الصفحة الرئيسي (`#0e1117`) ويجعل ألوان العناوين بيضاء، مما عطل تطبيق الثيم الفاتح المحدد في `.streamlit/config.toml` ومزج عناصر فاتحة مع خلفية داكنة مشوهة.

2. **تسرب أوسمة HTML وقص الأرقام:**
   - تم التخلص من أي تداخل في الأوسمة وإصلاح الحشو الداخلي للبطاقات ليصبح `14px 14px` وضبط الخط بدقة لتظهر كافة المبالغ (`$2,945.00` و`$1,525.50`) كاملة دون أي قص أو نقاط حذف (`...`).
   - تصحيح سلوك التمرير في أداة الالتقاط Playwright بضمان استدعاء `window.scrollTo(0, 0)` قبل التقاط كل صورة لضمان بدء اللقطة من أعلى الترويسة دائماً.

### الحل الجذري المنفذ
1. حذف كتلة الـ CSS المظلمة المخالفة بالكامل من `app.py`.
2. حصر التحكم البصري الكامل في دالة مركزية واحدة: `get_layout_css(lang)` في [`src/retailmind/ui/i18n.py`](file:///c:/Users/HP/Desktop/RetailMind%20A/src/retailmind/ui/i18n.py).
3. فرض هوية الـ SaaS الفاتحة عبر كافة الحاويات:
   - خلفية عاجية دافئة موحدة: `#FCFBF9` على `.stApp, [data-testid="stAppViewContainer"], .main, section.main, [data-testid="stHeader"]`.
   - أسطح البطاقات والحاويات بلون أبيض ناصع: `#FFFFFF` مع حدود ناعمة `#E8E5DF`.
   - الخطوط والعناوين بلون كحلي داكن فاخر: `#0F172A`.
   - التمييزات واللكنات الأساسية باللون الأخضر الزمردي: `#059669`.
   - اللكنات الذهبية المحسوبة: `#D97706` لشارات الحوكمة والموافقة البشرية.
   - شريط جانبي فاتح أنيق مع إخفاء دوائر الراديو التقليدية وتحويلها إلى أزرار تنقل SaaS ناعمة.
