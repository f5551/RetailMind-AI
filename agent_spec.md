# RetailMind AI — Agent Specification

## 1. Goal
RetailMind AI is an autonomous single-agent retail analytics assistant that deterministically validates, inspects, and analyzes uploaded CSV sales data to deliver verified performance rankings, anomaly detections, and user-approved audit-logged business reports via standard Model Context Protocol (MCP) tool execution.

## 2. Tools (Exactly 8 Allowed MCP Tools)
All arithmetic and data processing operations are executed deterministically by Python tools; the LLM never fabricates calculations.
1. `inspect_dataset(session_id: str) -> DatasetOverview`: Returns row count, column names, detected data types, date span, and sample rows.
2. `validate_dataset(session_id: str) -> ValidationReport`: Checks required columns, invalid dates, null values, negative values, and schema compliance.
3. `summarize_sales(session_id: str, group_by: Optional[str] = None) -> SalesSummary`: Computes total orders, net revenue, total units, and profit (if `unit_cost` present).
4. `rank_products(session_id: str, metric: str = "revenue", top_n: int = 5, ascending: bool = False) -> ProductRanking`: Ranks products by revenue, units, or profit.
5. `compare_periods(session_id: str, period_a: DateRange, period_b: DateRange) -> PeriodComparison`: Computes delta and percentage change in revenue and units.
6. `detect_anomalies(session_id: str, column: str = "revenue", method: str = "zscore", threshold: float = 2.5) -> AnomalyList`: Flags statistical sales outliers.
7. `segment_sales(session_id: str, dimension: str) -> SegmentAnalysis`: Groups metrics by `category`, `region`, or customer dimension.
8. `generate_report(session_id: str, title: str, sections: List[ReportSection], format: str = "markdown") -> ReportResult`: **WRITE ACTION** (requires explicit user approval). Writes a sanitized summary report to `reports/`.

## 3. Termination Conditions
The agent loop stops immediately upon encountering any of the following:
1. `max_turns = 8`: Hard limit on reasoning turns per task to prevent infinite loops.
2. `budget_per_task_usd = $0.10`: Dollar cap evaluated before and after each LLM call (Gemini 3.1 Flash-Lite Standard: $0.25/1M input, $1.50/1M output tokens).
3. `final_answer`: Concluding natural-language synthesis generated by the model once analytical goals are satisfied.
- **Error Semantics**: Tool execution failures return structured error dictionaries; the agent is allowed one corrective retry. Unrecoverable failures terminate with an explicit explanation.

## 4. Permission Policy (`ask_on_write`)
- Tools 1–7 are read-only and execute automatically.
- Tool 8 (`generate_report`) is a state-changing write action. The backend execution engine pauses the loop, displays the pending action and parameters to the user, and proceeds only upon receipt of cryptographic or explicit session approval (`status="APPROVED"`). Denial aborts write execution without crashing.

## 5. CSV Data Contract & Integrity Rules
- **Required Columns**: `date` (ISO-8601 `YYYY-MM-DD`), `product` (string), `quantity` (numeric), `unit_price` (numeric >= 0).
- **Optional Columns**: `unit_cost` (numeric >= 0), `category` (string), `region` (string), `order_id` (string).
- **Arithmetic Rules**: Net Revenue = $\sum(\text{quantity} \times \text{unit\_price})$. Returns are represented by $\text{quantity} < 0$ and reduce net revenue.
- **Profit Policy**: Profit and margin are calculated iff `unit_cost` is present for all valid rows; otherwise returned explicitly as `"UNAVAILABLE"`.
- **Integrity**: Missing required values are quarantined. Leading formula characters (`=`, `+`, `-`, `@`) in cells are sanitized against CSV injection.

## 6. Illustrative Input/Output Examples (Designed Synthetic Baseline)
*Baseline Synthetic Dataset*: `2026-01-05,Wireless Mouse,Electronics,5,25.00,North` | `2026-01-15,Gaming Headset,Electronics,3,60.00,West` | `2026-01-20,Wireless Mouse,Electronics,-1,25.00,North` (Return)

**Example 1: Top Product by Revenue**
- *Input*: "Which product generated the highest net revenue?"
- *Agent Actions*: `validate_dataset(session_id)` -> `rank_products(session_id, metric="revenue", top_n=1)`
- *Output*: "The top product by net revenue is **Gaming Headset** with $180.00 (3 units at $60.00). Wireless Mouse generated $100.00 net revenue (4 net units after 1 returned unit)."

**Example 2: Anomaly Detection**
- *Input*: "Are there any unusual transaction amounts in the uploaded sales data?"
- *Agent Actions*: `detect_anomalies(session_id, column="revenue", method="zscore", threshold=2.5)`
- *Output*: "No statistical revenue anomalies were detected at threshold 2.5. Transaction values range from -$25.00 (return) to $180.00."

**Example 3: Export Report (Approval-Gated)**
- *Input*: "Generate an executive sales report summarizing our regional performance."
- *Agent Actions*: `segment_sales(dimension="region")` -> Requests approval for `generate_report` -> User confirms -> `generate_report(...)`
- *Output*: "Sales report generated successfully at `reports/regional_summary_20260120.md` after your approval. Total net revenue across North and West regions was $280.00."

## 7. Measurable Acceptance Criteria
1. Exact zero arithmetic discrepancies between tool JSON output and synthesized agent response.
2. 100% of write operations halted until approval confirmation is recorded.
3. Total cost per standard analytic task maintained strictly $\le \$0.10$.
